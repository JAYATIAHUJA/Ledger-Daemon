Hours of reconciliation,
settled before you chase

Every automated decision carries its own receipt, and every doubtful one waits for a human. The daemon does the grunt work; your team keeps the judgment.

  • 01
    Payments find their invoice before you do

    Exact bank references first, then amounts inside the settlement window, then split settlements, then the narration itself — in that order, never the reverse.

  • 02
    Every decision ships with a receipt

    Which rows it read, the arithmetic that has to add up, and the rule that fired. Anyone can re-check it without trusting the engine.

  • 03
    TDS-paying customers are never dunned

    A shortfall that is exactly 1, 2 or 10% statutory TDS is a legally settled invoice — the daemon marks it paid and points you to Form 26AS instead.

  • 04
    When the data shifts, it pauses itself

    If your bank feed stops looking like the one it learned from, fuzzy matching switches itself off and waits — no silent wrong guesses.

This is the product’s own reading layer, running in your browser. Paste a line from your real statement — nothing you type is sent anywhere.

The daemon reads references, invoice numbers and names as typed evidence — it structurally cannot read an instruction, an amount or a verdict out of narration text. That’s what keeps a hostile bank line from ever moving money.

What we tested it on

500-order simulated businesses

Messy narrations, late settlements, split payouts, refunds, TDS deductions and duplicate references — worlds where we know the true answer for every order, so accuracy is measured, not assumed.

Real bank statement formats

HDFC and ICICI netbanking CSV exports parse straight in — Indian number formats, reference columns and all. Unrecognised layouts stop loudly instead of guessing about money.

Live Razorpay test mode

Real orders, payments and settlements from the Razorpay sandbox flow through the same pipeline. Live keys are refused by design — it cannot touch production money.

Across every run: 100% of already-paid orders blocked from being chased, with ₹0 wrongly chased — and the code to reproduce it is open.

Up and running in a minute

One requirement: Python 3.11+. No accounts, no keys, no cloud.

1Install
git clone https://github.com/JAYATIAHUJA/razorpay-hack.git
cd razorpay-hack/ledger-daemon
python -m pip install -e .
2See it work on a full business
python -m ledger_daemon ui   # opens the chase list in your browser

A 500-order world is generated, reconciled and proven — you get the screen from the top of this page, live and clickable.

3Point it at your own statement
python -m ledger_daemon import-statement bank.csv --out data/live
python -m ledger_daemon ui --dir data/live

Your HDFC/ICICI export becomes the bank feed. Everything stays on your machine.
